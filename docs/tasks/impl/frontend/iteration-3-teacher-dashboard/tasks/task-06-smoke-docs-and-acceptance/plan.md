# Задача: Smoke, документация и приёмка итерации

## Цель

Зафиксировать как проверять итерацию 3 локально, пройти базовый чек-лист качества React/Next и закрыть документацию.

## Состав работ

- **README / docs:** в [`README.md`](../../../../../README.md) или [`web/README.md`](../../../../../web/README.md) добавить короткий подпункт «Дашборд преподавателя»: URL `/dashboard`, требование роли teacher, ссылка на [`docs/tech/api-contracts.md`](../../../../../tech/api-contracts.md) для демо username и `flow_id`.
- **Чек-лист smoke** (ручной):
  - логин преподавателя → `/dashboard`;
  - KPI + график загружаются;
  - вопросы: первая страница + при наличии данных вторая страница через cursor;
  - сдачи: открытие Sheet, ссылки материалов;
  - матрица: скролл, tooltip;
  - студент (отдельный вход): сообщение о недоступности teacher-dashboard, приложение не падает.
- **Качество:** пройти рекомендации skill **`vercel-react-best-practices`** для новых client-компонентов (границы клиента/сервера, лишние перерисовки — по минимуму).

## DoD

- Инструкции воспроизводимы «с нуля» по существующим Makefile-целям.
- `make web-lint` и `make web-build` проходят после всех задач 1–5.
- Обновлён корневой [`docs/tasks/impl/frontend/iteration-3-teacher-dashboard/summary.md`](../../summary.md) при фактическом завершении реализации (делается агентом после кода — не в рамках только планирования).

## Проверки

- Полный прогон smoke из чек-листа.
- При необходимости — заметка об исключениях из best practices в summary итерации.
