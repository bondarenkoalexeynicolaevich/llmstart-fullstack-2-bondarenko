# Задача 03: Спецификация чата с ассистентом (виджет и полноэкранный)

## Цель

Описать два UX-контура одной истории диалога: плавающий виджет на всех страницах и маршрут «Чат»; состояния и API (детали — task-05 / OpenAPI).

## Данные

- Сообщения хранятся как `DialogMessage`: `participant_id`, `role` (`user` \| `assistant` \| `system`), `content`, `created_at` — [`docs/data-model.md`](../../../../../data-model.md).
- Контекст сессии веба: `participant_id` + `flow_id` после входа (см. task-04).

## Плавающий виджет

- **FAB** (кнопка) в углу экрана на всех основных маршрутах.
- По клику — раскрытие **панели** (предпочтительно `Sheet`/`Drawer` снизу на mobile, справа на desktop; высота ~40–60vh в свернутом виде, скролл ленты).
- Содержимое: список сообщений (простая лента), поле ввода, кнопка отправки, индикатор отправки.
- Не дублировать навигацию; ссылка «Открыть полностью» → `/chat`.

## Страница «Чат»

- Маршрут `/chat`: та же лента и ввод, шире по ширине, фокус на переписке.
- Компоненты ленты и ввода **общие** с виджетом.

## Сообщение (UI)

| Поле | Тип |
|------|-----|
| `id` | UUID |
| `role` | `user` \| `assistant` \| `system` (в UI показывать user/assistant; system скрывать или показывать как служебное — по умолчанию скрыть) |
| `content` | string |
| `created_at` | ISO 8601 |

## Операции

- **Загрузка истории:** `GET /v1/participants/{participant_id}/dialog-messages?flow_id={flow_id}&limit=&cursor=` — сервер проверяет, что участник относится к потоку и что токен сессии имеет право читать этот `participant_id`.
- **Отправка (веб):** `POST /v1/participants/{participant_id}/dialog-messages` с телом `{ "content": "..." }` и тем же контролем доступа; ответ — созданные/обновлённые id и текст ответа ассистента (см. схему OpenAPI). Бот по-прежнему может использовать `POST /v1/dialog-messages` с `telegram_user_id`.

**Примечание (KISS):** дублирование двух POST-путей допустимо на MVP: бот — существующий контракт; веб — привязка к `participant_id`.

## Состояния

- Загрузка истории: скелетон/спиннер в ленте.
- Отправка: блокировка кнопки, индикатор; оптимистичный UI опционально (итерация 5).
- Ошибка: сообщение под полем ввода + retry.
- Offline: деактивировать отправку, показать подсказку (если `navigator.onLine` false).

## Безопасность UI

- Не логировать текст сообщений в `console.log` в production-сборке.
